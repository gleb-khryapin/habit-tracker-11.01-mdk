# Трекер привычек — требования (MVP)

> Версия 1.0 от 09.10.2026. Документ — источник правды для тест-дизайна.
> Если поведение приложения расходится с этим документом — это баг (либо в коде, либо в документе).

## 1. Назначение

Веб-приложение, в котором пользователь заводит привычку на N дней, каждый день отмечает её выполнение
и после N дней подряд получает мотивирующее сообщение о пользе сделанного.

## 2. Роли

| Роль | Как появляется | Что может |
|---|---|---|
| Гость | — | Зарегистрироваться, войти |
| Пользователь (`user`) | Регистрация | Управлять **своими** привычками: создать, изменить, удалить, отметить выполнение |
| Администратор (`admin`) | Только через seed (зарегистрироваться админом нельзя) | Всё, что пользователь, + добавлять и удалять **предложенные привычки** (шаблоны) |

Пользователь видит и изменяет только свои привычки. Чужая привычка для него «не существует» (404, а не 403).

## 3. Сущности и правила валидации

Строковые поля, **кроме пароля**, перед проверкой обрезаются по краям (trim). Длина считается в символах после обрезки
(смайл — 1 символ).

### 3.1. Пользователь

| Поле | Правило |
|---|---|
| `username` | 3–20 символов, только латиница, цифры и `_`. Уникален **без учёта регистра** (`Gleb` и `gleb` — один логин) |
| `password` | 6–64 символа, любые символы. Хранится только хэш |
| `role` | `user` или `admin`. При регистрации всегда `user` |

### 3.2. Предложенная привычка (шаблон)

Создаёт админ. Пользователь выбирает из списка шаблонов при создании привычки.

| Поле | Обязательное | Правило |
|---|---|---|
| `title` | да | 1–50 символов. Уникально среди шаблонов без учёта регистра |
| `emoji` | нет | Один из разрешённых смайлов (п. 3.5). Не передан или пустой → `🎯` |
| `description` | нет | 0–200 символов |
| `completionMessage` | да | 10–500 символов. Сообщение, которое получит пользователь после выполнения |

`completionMessage` в списке шаблонов видит только админ (для пользователя это сюрприз).

### 3.3. Привычка пользователя

| Поле | Обязательное | Правило |
|---|---|---|
| `title` | да (для своей) | 1–50 символов. Уникально среди **активных** привычек этого пользователя без учёта регистра. Выполненная или прерванная привычка с тем же названием не мешает |
| `emoji` | нет | Один из разрешённых смайлов. Не передан или пустой → `🎯` |
| `targetDays` | да | Целое число 1–365 — сколько дней подряд нужно выполнять |
| `hoursPerDay` | нет | `null` или число от 0.5 до 24 с шагом 0.5 (0.5, 1, 1.5 … 24). Только информационное поле, на засчитывание дня не влияет |
| `templateId` | нет | Если передан — `title`, `emoji` и сообщение берутся из шаблона, а `title` и `emoji` из запроса **игнорируются**. Несуществующий `templateId` → 400 |
| `startDate` | — | Заполняется автоматически: дата создания. **Это день 1** |

Вычисляемые поля (в БД не хранятся):

| Поле | Как считается |
|---|---|
| `progress` | Количество отметок выполнения |
| `status` | `active`, `completed` или `failed` (п. 4) |
| `checkedToday` | Есть ли отметка за сегодня |
| `failedOn` | Для `failed` — дата первого пропущенного дня, иначе `null` |

### 3.4. Отметка выполнения

| Поле | Правило |
|---|---|
| `date` | Всегда «сегодня» по дате сервера. Отметить прошлый или будущий день нельзя |
| — | Одна отметка на привычку в день |

### 3.5. Разрешённые смайлы

`🎯 💧 🏃 📚 🧘 😴 🍎 💪 📝 🎸 🌱 📵 🧠 🚶 🎨 💻`

Любой другой символ или строка → 400.

## 4. Жизненный цикл привычки

```
            отметка (progress < targetDays)
             ┌──────┐
             ▼      │
 создание → active ─┴── отметка, progress = targetDays ──→ completed (+ сообщение)
             │
             └── прошёл день без отметки ──→ failed (только удалить)
```

Правила:

1. День 1 — день создания. Отмечать нужно **каждый** день: день 1, день 2 … день N.
2. Если календарный день закончился без отметки, привычка становится `failed`. `failedOn` — этот пропущенный день.
   Пример: создана 10.10, отметки 10.10 и 11.10, 12.10 отметки нет → 13.10 статус `failed`, `failedOn = 12.10`.
3. В течение дня привычка без сегодняшней отметки остаётся `active`: день ещё не закончился.
4. Отметка, после которой `progress = targetDays`, переводит привычку в `completed` и открывает сообщение:
   - для привычки из шаблона — `completionMessage` шаблона (копируется в привычку при создании, поэтому удаление шаблона не влияет);
   - для своей привычки — фраза из общего пула (п. 7), номер фразы = `id привычки % 5`.
5. `completed` и `failed` — конечные статусы. Такую привычку нельзя отметить или изменить, можно только удалить.
6. «Сегодня» определяется по локальной дате сервера.

## 5. Функции

| # | Функция | Кто |
|---|---|---|
| F1 | Регистрация (после неё вход выполняется автоматически), вход, выход | Гость / все |
| F2 | Создать привычку: из шаблона или свою; задать срок в днях и, по желанию, часы в день | user |
| F3 | Просмотреть список своих привычек с прогрессом и статусом | user |
| F4 | Отметить выполнение за сегодня | user |
| F5 | Изменить привычку: `title`, `emoji`, `targetDays`, `hoursPerDay` | user |
| F6 | Удалить привычку (вместе со всеми отметками), с подтверждением в UI | user |
| F7 | Добавить и удалить предложенную привычку | admin |

### Правила изменения (F5)

- Можно менять только `active` привычку.
- Новый `targetDays` должен быть **больше** текущего `progress`. Пример: отмечено 5 дней → минимум 6. Иначе 400.
- Уникальность `title` проверяется так же, как при создании (сама привычка не считается дублем).
- `startDate`, `progress` и `templateId` не меняются.

### Удаление шаблона (F7)

Привычки, созданные из шаблона, остаются без изменений (`templateId` становится `null`).

## 6. REST API

Базовый путь — `/api`. Формат — JSON. Документация — Swagger UI: `/swagger`.
Аутентификация — cookie `habits_auth` (выдаётся при входе или регистрации, живёт 7 дней).

Формат ошибки всегда один:

```json
{ "error": "Понятный текст ошибки на русском" }
```

### Коды ответов

| Код | Когда |
|---|---|
| 200 | Успешное чтение или изменение |
| 201 | Создано: пользователь, привычка, шаблон, отметка |
| 204 | Успешно, тела нет (удаление, выход) |
| 400 | Ошибка валидации, некорректный JSON, неверный тип поля (например, `"targetDays": "21"`) |
| 401 | Не выполнен вход, неверный логин или пароль |
| 403 | Не админ вызывает админский метод |
| 404 | Нет такого объекта или он чужой; нет такого метода API |
| 405 | HTTP-метод не поддерживается для этого адреса (например, `PATCH /api/habits/1`) |
| 409 | Конфликт: дубль названия/логина, повторная отметка за день, действие с `completed`/`failed` привычкой |
| 415 | Тело запроса не JSON (неверный `Content-Type`) |

Типы полей строгие: число в кавычках (`"21"`) или дробное число в целом поле (`21.5`) → 400.
Лишние поля в теле запроса игнорируются (например, `"role": "admin"` при регистрации).

Порядок проверок для привычки: 401 (нет входа) → 404 (нет или чужая) → 409 (уже `completed`/`failed`)
→ 400 (валидация полей, первая найденная ошибка) → 409 (дубль названия / повторная отметка).

### Методы

| Метод | Путь | Доступ | Успех |
|---|---|---|---|
| POST | `/api/auth/register` | все | 201 + пользователь |
| POST | `/api/auth/login` | все | 200 + пользователь. Логин без учёта регистра. Пустые поля → 400, неверная пара → 401 |
| POST | `/api/auth/logout` | все | 204 |
| GET | `/api/auth/me` | вход | 200 + пользователь |
| GET | `/api/meta` | все | 200: `today`, список смайлов, тестовый режим |
| GET | `/api/templates` | вход | 200 + список шаблонов |
| POST | `/api/templates` | admin | 201 + шаблон |
| DELETE | `/api/templates/{id}` | admin | 204 |
| GET | `/api/habits` | вход | 200 + список своих привычек |
| GET | `/api/habits/{id}` | вход | 200 + привычка |
| POST | `/api/habits` | вход | 201 + привычка |
| PUT | `/api/habits/{id}` | вход | 200 + привычка (передаются все поля: `title`, `emoji`, `targetDays`, `hoursPerDay`) |
| DELETE | `/api/habits/{id}` | вход | 204 |
| POST | `/api/habits/{id}/checkins` | вход | 201 + привычка (если она стала `completed`, в ней есть `completionMessage`) |

Пример привычки в ответе:

```json
{
  "id": 7,
  "title": "Чтение",
  "emoji": "📚",
  "targetDays": 21,
  "hoursPerDay": 0.5,
  "templateId": 3,
  "startDate": "2026-10-09",
  "progress": 5,
  "status": "active",
  "checkedToday": true,
  "failedOn": null,
  "completedOn": null,
  "completionMessage": null,
  "createdAt": "2026-10-09T18:30:00Z"
}
```

`completionMessage` заполнен только у `completed` привычки.

| № | Фраза |
|---|---|
| 0 | Финиш! Каждый из этих дней был маленькой победой над «потом» — и вместе они сложились в большую. |
| 1 | Весь срок без единого пропуска. Это и есть дисциплина: не настроение, а решение, которое ты принимаешь каждый день. |
| 2 | Привычка закреплена! Теперь это не усилие, а часть тебя. Дальше будет только легче. |
| 3 | Готово! Теперь ты точно знаешь: если решить — получится. Запомни это чувство и бери новую цель. |
| 4 | Регулярность сильнее таланта — и теперь у тебя есть доказательство. Можно гордиться, это заслуженно. |

## 8. Тестовый режим (только окружение Development)

Нужен, чтобы проверять сценарии «прошло 21 день» и «пропущен день» без ожидания реального времени.
В Production этих методов нет (404).

| Метод | Путь | Что делает |
|---|---|---|
| PUT | `/api/test/clock` | Тело `{"today": "2026-10-30"}` — подменить «сегодня» |
| DELETE | `/api/test/clock` | Вернуть реальную дату |
| POST | `/api/test/reset` | Пересоздать БД с seed-данными и сбросить часы. Все сессии становятся недействительными |

Когда дата подменена, в UI сверху показывается плашка «🧪 Тестовая дата».

|---|---|---|---|
| `admin` | `admin123` | admin | — |

Плюс 6 предложенных привычек: «Пить воду», «Утренняя зарядка», «Чтение», «Медитация», «Сон до 23:00», «Утро без соцсетей».

## 10. UI

- Страницы: `/` (вход и регистрация), `/habits.html` (мои привычки), `/admin.html` (админка).
- Без входа `/habits.html` и `/admin.html` перенаправляют на `/`. Не админ на `/admin.html` видит «Нет доступа».
- Ключевые элементы размечены атрибутом `data-testid`.
- Тёмная тема, фиолетовые акценты, минимализм.

## 11. Вне рамок MVP

Восстановление пароля, отмена сегодняшней отметки, отметка задним числом, напоминания, часовые пояса пользователей,
редактирование шаблонов, управление пользователями из админки, статистика.
