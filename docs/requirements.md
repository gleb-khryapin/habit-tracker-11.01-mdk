# Трекер привычек (десктоп) — требования (MVP)

> Версия 4.0 от 22.10.2026. Документ — источник правды для тест-дизайна.
> Если поведение приложения расходится с этим документом — это баг (либо в коде, либо в документе).

## 1. Назначение

Десктопное приложение для Windows: пользователь заводит привычку на N дней, каждый день отмечает её выполнение
и после N дней подряд получает мотивирующее сообщение о пользе сделанного.
Привычки группируются по категориям, о них можно поставить напоминания, а за успехи выдаются достижения.
Серия активных дней показывается «огоньком». Пользователи предлагают новые привычки в общий список через заявки,
которые рассматривает администратор. Изменения данных записываются в журнал, базу можно сохранить в резервную копию и восстановить.

## 2. Роли

| Роль | Как появляется | Что может |
|---|---|---|
| Гость | — | Зарегистрироваться, войти |
| Пользователь (`user`) | Регистрация | Управлять **своими** привычками: создать, изменить, удалить, отметить выполнение; фильтровать их по категории; настраивать напоминания; смотреть свои достижения и огонёк; **подавать заявки** на новые предложенные привычки |
| Администратор (`admin`) | Только из начальных данных (зарегистрироваться админом нельзя) | Всё, что пользователь, кроме подачи заявок, + добавлять и удалять **предложенные привычки**, **категории** и **фразы общего пула**; **рассматривать заявки**; смотреть **журнал действий**; делать **резервную копию** и восстанавливать из неё |

Пользователь видит только свои привычки, напоминания и достижения.
Роли хранятся в справочнике `roles`, у пользователя — ссылка на роль.

## 3. Сущности и правила валидации

Текстовые поля, **кроме пароля**, перед проверкой обрезаются по краям (пробелы в начале и в конце не считаются).

### 3.1. Пользователь

| Поле | Правило |
|---|---|
| Логин | 3–20 символов, только латиница, цифры и `_`. Уникален **без учёта регистра** (`Gleb` и `gleb` — один логин) |
| Пароль | 6–64 символа, любые символы. В БД хранится только хэш |
| Роль | `user` или `admin`. При регистрации всегда `user` |

### 3.2. Предложенная привычка

Создаёт админ. Пользователь выбирает её из списка при создании привычки.

| Поле | Обязательное | Правило |
|---|---|---|
| Название | да | 1–50 символов. Уникально среди предложенных привычек без учёта регистра |
| Смайл | да | Выбирается из списка (п. 3.5) |
| Категория | нет | Выбирается из списка категорий (п. 3.6) либо «Без категории» |
| Описание | нет | 0–200 символов |
| Сообщение после выполнения | да | 10–500 символов |

### 3.3. Привычка пользователя

| Поле | Обязательное | Правило |
|---|---|---|
| Название | да (для своей) | 1–50 символов. Уникально среди **активных** привычек этого пользователя без учёта регистра. Выполненная или прерванная привычка с тем же названием не мешает |
| Смайл | да (для своей) | Выбирается из списка (п. 3.5) |
| Категория | нет | Выбирается из списка категорий (п. 3.6) либо «Без категории». По умолчанию «Без категории» |
| Срок | да | Целое число 1–365 — сколько дней подряд нужно выполнять. По умолчанию 21 |
| Часы в день | нет | Не указаны либо число от 0.5 до 24 с шагом 0.5. Только информация, на засчитывание дня не влияет |
| Дата начала | — | Заполняется автоматически: дата создания. **Это день 1** |

Привычка «из списка» получает название, смайл, категорию и сообщение от предложенной привычки.
Сообщение копируется в привычку при создании, поэтому удаление предложенной привычки на неё не влияет.

### 3.4. Отметка выполнения

- Всегда за «сегодня». Отметить прошлый или будущий день нельзя.
- Одна отметка на привычку в день.

### 3.5. Смайлы

`🎯 💧 🏃 📚 🧘 😴 🍎 💪 📝 🎸 🌱 📵 🧠 🚶 🎨 💻`

### 3.6. Категория

Создаёт админ. Общий справочник для привычек и предложенных привычек.

| Поле | Обязательное | Правило |
|---|---|---|
| Название | да | 1–30 символов. Уникально без учёта регистра |

При удалении категории привычки и предложенные привычки из неё не удаляются, а становятся «Без категории».

### 3.7. Фраза общего пула

Создаёт админ. Фразы показываются после выполнения **своих** привычек (п. 6).

| Поле | Обязательное | Правило |
|---|---|---|
| Текст | да | 10–500 символов |

### 3.8. Напоминание

Создаёт пользователь для своей привычки «В процессе».

| Поле | Правило |
|---|---|
| Время | Часы 0–23 и минуты 0–59, хранится как `ЧЧ:ММ`. По умолчанию 20:00 |
| Состояние | Включено или выключено. Новое напоминание включено |

- У одной привычки не больше **5** напоминаний.
- Два напоминания одной привычки на одно и то же время создать нельзя.
- При удалении привычки её напоминания удаляются.

### 3.9. Достижение

Список достижений фиксированный, создаётся с начальными данными (п. 8). Пользователь его не меняет.

| Код | Смайл | Название | Условие |
|---|---|---|---|
| `first_habit` | 🌱 | Первый шаг | У пользователя есть хотя бы одна привычка |
| `first_checkin` | 🎯 | Начало положено | Есть хотя бы одна отметка выполнения |
| `streak_7` | 💪 | Неделя подряд | В одной привычке отмечено 7 дней или больше |
| `streak_30` | 🏃 | Марафонец | В одной привычке отмечено 30 дней или больше |
| `first_completed` | 📝 | Финишёр | Есть хотя бы одна выполненная привычка |
| `completed_3` | 🧠 | Три победы | Выполненных привычек три или больше |
| `flame_7` | 🔥 | Огонь недели | Рекорд огонька (п. 3.11) — 7 дней или больше |

### 3.10. Заявка на предложенную привычку

Подаёт пользователь, рассматривает администратор.

| Поле | Обязательное | Правило |
|---|---|---|
| Название | да | 1–50 символов. Не совпадает без учёта регистра ни с предложенной привычкой из списка, ни с другой заявкой «На рассмотрении» (от любого пользователя) |
| Смайл | да | Из списка (п. 3.5) |
| Категория | нет | Одна из категорий или «Без категории» |
| Описание | нет | 0–200 символов |
| Сообщение после выполнения | да | 10–500 символов |
| Статус | — | «На рассмотрении» → «Одобрена» или «Отклонена». Другие значения база не примет |
| Причина отказа | при отклонении | 5–200 символов |
| Дата подачи, дата рассмотрения | — | Заполняются автоматически |

- У одного пользователя может быть не больше **3** заявок «На рассмотрении» одновременно.
- Отозвать (удалить) можно только свою заявку «На рассмотрении». Одобренные и отклонённые остаются в истории.

### 3.11. Огонёк (серия активных дней)

- **Активный день** — календарный день, в который пользователь отметил хотя бы одну привычку.
- **Огонёк** — сколько активных дней идёт подряд, заканчивая сегодняшним днём. Если сегодня отметок ещё нет,
  счёт заканчивается вчерашним днём: огонёк ещё горит, но погаснет, если день закончится без отметки.
- **Рекорд** — самая длинная серия активных дней за всё время.
- Активные дни хранятся отдельно от отметок. Удаление привычки не уменьшает огонёк и рекорд.

## 4. Жизненный цикл привычки

Статус в БД не хранится — он вычисляется по дате начала, числу отметок и сегодняшней дате.

| Статус | Условие |
|---|---|
| Выполнена | Отметок столько же, сколько дней в сроке |
| Прервана | Не выполнена, и уже прошёл день, за который нет отметки |
| В процессе | Всё остальное |

Правила:

1. День 1 — день создания. Отмечать нужно **каждый** день: день 1, день 2 … день N.
2. Если календарный день закончился без отметки, привычка становится «Прервана».
   Пример: создана 10.10, отметки 10.10 и 11.10, 12.10 отметки нет → 13.10 статус «Прервана», пропущенный день — 12.10.
3. В течение дня привычка без сегодняшней отметки остаётся «В процессе»: день ещё не закончился.
4. Отметка, после которой число отметок равно сроку, делает привычку «Выполнена» и показывает окно с сообщением:
   - для привычки из списка — сообщение предложенной привычки;
   - для своей привычки — фраза из общего пула, закреплённая за ней при создании (п. 6).
5. «Выполнена» и «Прервана» — конечные статусы. Такую привычку нельзя отметить или изменить, можно только удалить.

### Огонёк (F13)

Показывается рядом с заголовком «Мои привычки». Текст зависит от состояния:

| Состояние | Текст | Цвет |
|---|---|---|
| Активных дней ещё не было | «🔥 Отметь привычку, чтобы зажечь огонёк» | приглушённый |
| Огонёк погас (вчера и сегодня отметок нет) | «🔥 Огонёк погас · рекорд N дн.» | приглушённый |
| Сегодня уже есть отметка | «🔥 Огонёк: N дн. · рекорд M дн.» | оранжевый |
| Сегодня отметок нет, вчера были | «🔥 Огонёк: N дн. · отметь сегодня, иначе погаснет» | приглушённый |

Огонёк пересчитывается сразу после отметки. Работает с тестовой датой (п. 7).

### Заявки (F14, F15)

- Пользователь открывает окно кнопкой «Мои заявки», администратор — кнопкой «Заявки».
- Пользователь видит свои заявки (новые сверху) со статусом. У выбранной показываются категория, описание и итог рассмотрения:
  дата одобрения или дата и причина отказа.
- Администратор видит только заявки «На рассмотрении» (старые сверху) с автором, категорией, описанием и сообщением.
- **Одобрить:** заявка получает статус «Одобрена», а в список предложенных привычек добавляется привычка с её полями.
  Оба изменения выполняются вместе (в одной транзакции). Если в списке уже есть привычка с таким названием,
  одобрить нельзя — показывается ошибка с подсказкой отклонить заявку.
- **Отклонить:** нужна причина 5–200 символов. Заявка получает статус «Отклонена».

### Журнал действий (F16)

- Записи создаёт сама база данных (триггеры), приложение их только читает.
- Записываются: регистрация пользователя; создание, изменение и удаление привычки; отметка выполнения;
  добавление и удаление предложенной привычки; подача, рассмотрение и отзыв заявки.
- Изменение привычки записывается, только если поменялись название, смайл, категория, срок или часы.
  В записи видно старое и новое название и срок.
- Поля записи: время (часы компьютера, не тестовая дата), действие («добавление», «изменение», «удаление»), таблица, описание.
- Показываются последние 500 записей, новые сверху. После создания начальных данных журнал пуст.

### Резервная копия (F17)

- «Сделать резервную копию» сохраняет все данные в выбранный файл `.sql`: по одной команде `INSERT` на строку каждой таблицы.
- «Восстановить из копии» принимает только файл, созданный этой кнопкой (первая строка `-- habit_tracker backup`). Иначе ошибка
  «Файл не является резервной копией приложения». Восстановление выполняется в одной транзакции: при ошибке данные не меняются.
- Журнал действий и активные дни восстанавливаются ровно такими, как в копии: записи, которые триггеры создают при восстановлении, удаляются.
- Перед восстановлением текущие данные автоматически сохраняются в `habits-before-restore.sql` рядом с программой.
- После восстановления нужно войти заново.

### Правила изменения (F5)

- Менять можно только привычку «В процессе».
- Новый срок должен быть **больше** числа уже отмеченных дней. Пример: отмечено 5 дней → минимум 6.
- Уникальность названия проверяется так же, как при создании (сама привычка не считается дублем).
- Дата начала и отметки не меняются.

### Фильтр по категории (F8)

- Над списком — выпадающий список: «Все категории» и все категории по алфавиту. По умолчанию «Все категории».
- При выборе категории в списке остаются только привычки этой категории. Порядок по статусам сохраняется.
- Если в выбранной категории привычек нет, под списком показывается «В этой категории привычек нет.».

### Напоминания (F9)

- Окно «Напоминания» открывается для выбранной привычки «В процессе».
- Напоминание срабатывает, когда текущее время компьютера (часы и минуты) совпало с его временем и одновременно:
  приложение открыто и пользователь вошёл; напоминание включено; привычка «В процессе»; сегодняшней отметки ещё нет.
- Срабатывание — окно «Напоминание · ЧЧ:ММ» со списком привычек, которые пора отметить.
  Несколько привычек с одним временем показываются одним окном.
- Время напоминания берётся с часов компьютера; тестовая дата (п. 7) на него не влияет.
- Пропущенные напоминания (приложение было закрыто) не показываются.

### Достижения (F10)

- Условия проверяются после создания привычки и после отметки выполнения.
- Новое достижение показывается окном «Новое достижение» и записывается с сегодняшней датой.
  Если отметка завершила привычку, сначала показывается сообщение о выполнении, потом достижения.
- Достижение выдаётся один раз и не отбирается, даже если привычку потом удалили.
- В окне «Достижения» — все достижения: у полученных дата, у остальных «—», сверху «Получено: X из 7».

### Поведение кнопок главного окна

| Выбрана привычка | «Отметить сегодня» | «Напоминания» | «Изменить» | «Удалить» |
|---|---|---|---|---|
| В процессе, сегодня не отмечена | доступна | доступна | доступна | доступна |
| В процессе, сегодня отмечена | недоступна, текст «✓ Сегодня отмечено» | доступна | доступна | доступна |
| Выполнена или прервана | недоступна | недоступна | недоступна | доступна |
| Список пуст | недоступна | недоступна | недоступна | недоступна |

Кнопки «Достижения» и «Мои заявки» (у администратора — «Заявки») доступны всегда.
Кнопки «Журнал», «Предложенные привычки», «Категории» и «Фразы» видны только администратору.

### Ошибки

Ошибка ввода показывается окном «Проверь данные» с текстом, что именно не так; данные при этом не сохраняются, форма остаётся открытой.

## 6. Общий пул сообщений (для своих привычек)

Пул хранится в БД, его меняет админ (F12). Правила:

1. Фраза закрепляется за своей привычкой **при создании**: фразы пула берутся по возрастанию `id`,
   номер фразы (с нуля) = `id привычки % количество фраз`.
2. Добавление новых фраз на уже созданные привычки не влияет.
3. Если пул пуст в момент создания или закреплённую фразу удалили, показывается стандартное сообщение:
   «Привычка выполнена! Весь срок без единого пропуска — отличная работа.»

Начальный пул:

| № | Фраза |
|---|---|
| 0 | Финиш! Каждый из этих дней был маленькой победой над «потом» — и вместе они сложились в большую. |

## 7. Тестовая дата

Чтобы проверять «прошло 21 день» и «пропущен день» без ожидания, приложение можно запустить с подменой сегодняшней даты:

```
dotnet run -- --today 2026-10-30
```

В главном окне рядом с датой появляется пометка «(тестовая дата)».

Создаются при первом запуске, когда в базе `habit_tracker` ещё нет пользователей. Чтобы вернуть их, запусти приложение с параметром `--reset-db`.
